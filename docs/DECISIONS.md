# Decision log

Short entries, newest last. Each says what we decided, why, and what we gave up. Times are Europe/Helsinki.

| # | When | Decision | Why | Trade-off / what we gave up |
|---|------|----------|-----|-----------------------------|
| D1 | Sat 01:15 | Frame the concept as **"the AI reviewer works under a mandate"**: a signed, versioned policy per repo/area says what the AI may clear alone and what goes to a named human. | Tieto's principles (named owner, AI is advice not approval, depth follows risk, trust earned per area) are all statements about *authority*. A mandate makes that authority explicit, versioned and auditable. Pattern borrowed from our other entry, Sous (AI purchasing agents under a signed mandate). | A mandate needs an owner to write and maintain it; a fresh repo has no track record, so everything starts at `ask`. |
| D2 | Sat 01:20 | **Deterministic checks first, models second.** Build, targeted tests, "new tests fail without the fix", public API, analyzers run before any model reads the diff, and models must cite their results. | Model output is the part that can hallucinate; tool output can't. Ordering them this way lets the models argue about evidence instead of inventing it. | Running builds and tests costs minutes per change; some areas (UI, perf) need checks we don't have here. |
| D3 | Sat 01:20 | **Two independent reviewers from different vendors** (Claude and Codex), same brief, no shared context. A requirement is only "proven" if both agree with verified evidence and the mandated checks pass; otherwise the AI **refuses to decide** and says why. | Same-vendor reviewers share blind spots. Disagreement is cheap, observable signal of uncertainty, unlike self-reported confidence. | Twice the model cost; more refusals means more human routing at first. We accept that: a refusal is cheaper than an escape. *Later:* superseded by D8 (three reviewers, unanimity). |
| D4 | Sat 01:20 | **No evidence, no finding.** Every citation is machine-checked (file:line + exact quote, test name + outcome, check id, requirement clause). Unverifiable findings are dropped from the verdict but shown as "rejected" and counted against the reviewer. | Tieto rejects "confidence without evidence". Verification also gives us a per-reviewer hallucination rate for free. | A true finding with a sloppy citation is lost; we surface it as rejected so a human can still see it. |
| D5 | Sat 01:25 | Requirement IDs: until Tieto's official set arrives, use **placeholders derived from each upstream issue** (`REQ-<issue>-F1`...), marked `official: false`. | We couldn't find the official set in the challenge repo; work can't wait. | Our requirement split is our own reading of the issue and could be wrong; we re-run reviews when the official set lands. |
| D6 | Sat 01:30 | Codex's first review ran **before** deterministic facts existed; we keep it as-is and do a second pass with facts. | Shows that refusals turn into verdicts as evidence arrives, which is the behaviour we want. | Two Codex runs instead of one. |

| D8 | Sat 01:45 | **Three reviewers, unanimity.** Nemotron (NVIDIA, open weights) joins Claude and Codex as a full reviewer. With unanimity each added reviewer can only make the AI more cautious, which is the direction we want for an approval that a human signs. | More refusals, so more human routing, and one flaky API call refuses every clause of that change until it is re-run. |
| D9 | Sat 01:45 | **Gemini is the adjudicator, never a clearer.** It runs only on disputes (clause disagreements, uncorroborated blocker/major findings), sees both sides' cited evidence with the engine's verification results, and says which claims the evidence supports and what would settle the rest. Hard rule in `decide.apply_adjudication`: it can add reasons and route to a human, never turn a refused clause into proven. | A tie-breaker that can clear would be a single model approving the change, which is exactly what the mandate forbids. An evidence auditor still saves the owner time: it points at which side's citations hold up. | A third vendor's cost and latency on disputed changes, for advice that never changes a tier downward. *Later:* wired but not run (no key); every pack says "not adjudicated". |
| D10 | Sat 01:45 | **Confidentiality in the mandate.** `confidential: true` (repo or area) means only `self_hostable` reviewers (Nemotron: open weights) may read the code; the others are skipped, their files ignored, and the pack says who was excluded. The runner also refuses to send confidential code to a vendor-hosted endpoint. | Where the code goes is a policy decision with an owner, not a property of a script. MessagePack is open source, so it stays non-confidential. | A confidential change gets a one-reviewer panel, so its proofs are weaker (no cross-vendor disagreement signal); we need a self-hosted Nemotron endpoint before that is real. |
| D11 | Sat 02:20 | **Review JSON is untrusted input to the verifier** (security triage T2, C2, T3, C3). Only *substantive* evidence counts towards `min_verified_evidence` and a finding's support: a code quote at `head`/`base` in a file the change touches, a test with a claimed outcome that matches, a check with a claimed status that matches. Requirement quotes may verify but never count. `rev` must be `head` or `base`; paths must be relative and in the diff (base may also cite the mandate's `base_context_files`); git gets `--end-of-options`. Two verdicts for one clause count as none. Malformed items are rejected, never a crash. | A reviewer (or a diff steering it) could prove a clause by citing the clause itself, and a model-chosen `rev` reached `git show` as an option (it wrote a file). Each item that counts must now say something checkable about the change. | Real verdicts that cited only check ids lost weight: 2234 N2 and 2283 N1 are now also refused for thin evidence (Codex cited `tests.full_suite` without a status). | D12 | Sat 02:25 | **The engine says more than proven/refused, and nothing argues away a failing check.** (a) `held_before`: met, but its new tests already pass without the fix: not proven, routes at least `notify`, in residual risk.
